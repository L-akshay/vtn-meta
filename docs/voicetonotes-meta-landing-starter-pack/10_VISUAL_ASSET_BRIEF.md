# Visual asset brief

## Landing page visuals

The page should not rely on generated lifestyle imagery.

Priority:
1. real app screenshots
2. CSS-drawn phone shell
3. typography
4. subtle waveform/product micro-animation

This is more credible and more premium than AI-generated people holding phones.

## Screenshots to capture

Capture clean demo-state screens for:
- active recording/transcription
- completed transcript
- summary
- action items
- cleanup/formatting
- rephrase
- custom prompt
- import flow, only if currently supported

## Demo content

Use realistic but synthetic content.

Avoid:
- real names/emails
- medical patient details
- company confidential meetings
- lorem ipsum

## Device framing

Do not use a raster bezel.

Use:
- CSS outer shell
- rounded screen clipping
- subtle physical edge
- pill/dynamic-island-like cutout only if appropriate to the supplied screenshot
- one restrained phone shadow

## Ad creative reuse

The hero demo can later be recorded as a short ad creative:
- 9:16
- fast first-frame hook
- 3–5 second product proof
- CTA

But keep the website itself video-free.

## AI image generation

If marketing wants generated campaign artwork later, generate it as **campaign artwork**, not fake VoiceToNotes UI.

Any generated visual should leave the actual app screen area to be composited with a real screenshot afterward.
